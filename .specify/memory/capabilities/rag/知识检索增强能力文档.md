# 知识检索增强能力文档

> 能力标识：`rag`
> 文档层级：技术能力域
> 文档状态：文档解析器扩展与文档分块已汇总，其他 RAG 子能力待深度建模
> 更新日期：2026-07-30

## 1. 能力定位与边界

知识检索增强能力负责文档处理、向量化、检索增强及相关框架与资源适配。本次知识汇总覆盖“RAG 文档解析器扩展”和“LangChain4j 文档分块”，不把向量化、向量存储和检索策略的规划或局部实现扩写为已验证标准。

文档解析子能力当前提供：

- 框架无关的解析请求、解析结果信封、provider SPI、能力描述、注册表、选择器、解析轨迹和分类异常。
- Spring AI 与 LangChain4j 各自的 native provider、独立泛型注册表和框架边界适配。
- 共享的 MinerU 协议客户端与中立解析 provider。
- `DEFAULT` 与 `EXPLICIT` 两种选择模式，以及不执行静默 fallback 的失败语义。

文档分块子能力（LangChain4j 模块）当前提供：

- `recursive` 策略：基于 `DocumentByParagraphSplitter` 实现段落->句子->词->字符递归降级分块。
- `markdown-header` 策略：基于 `MarkdownHeaderParentSplitter` 实现 Markdown 标题层级分块 + 父子模式二次切割。
- 可配置的 chunkSize、overlap 和 titleLevel 参数。
- Facade 提供 `parseAndSplit`（解析+分块一站式）和 `split`（对已解析文档分块）两种入口。

## 2. 核心机制

| 机制 | 已验证事实 | 主要来源 | 可信状态 |
| --- | --- | --- | --- |
| 泛型 provider 契约 | `DocumentParseProvider<R>` 返回 `DocumentParseResult<R>`，公共层不绑定 Spring AI 或 LangChain4j 类型 | 公共接口、模块测试 | 已验证 |
| provider 注册 | 同一注册表内 provider 标识小写归一；重复标识立即失败，运行期不允许覆盖 | `DocumentParserRegistry`、注册表测试 | 已验证 |
| 解析器选择 | `DEFAULT` 固定选择 `native`；`EXPLICIT` 必须指定 provider；按可用性、文档类型、精确扩展名和所需特性校验 | `ParserSelection`、`DocumentParserSelector`、选择器测试 | 已验证 |
| 失败语义 | provider 不存在、不可用、不支持或执行失败时返回分类异常，不自动切换其他 provider | `DocumentParseError`、异常矩阵测试 | 已验证 |
| 原生对象直通 | native provider 的框架原生结果直接进入结果信封，不往返转换为公共中立对象 | Spring AI/LangChain4j provider 与测试 | 已验证 |
| MinerU 单次适配 | 共享 provider 生成中立 `ParsedDocument`，仅在框架边界转换一次 | 两个 MinerU 薄包装 provider 与适配测试 | 已验证 |
| 解析轨迹 | 记录 provider、耗时、源类型、输出格式、版本、后端和选择原因，不包含正文或认证信息 | `ParseTrace`、实施报告 | 已验证 |
| 递归分块策略 | `DocumentByParagraphSplitter` 实现段落->句子->词->字符递归降级，等价于 `DocumentSplitters.recursive()` | `LangChain4jDocumentSplitter`、分块测试 | 已验证 |
| Markdown 标题分块 | 按标题层级切分，维护标题栈处理层级回退，代码块内不检测标题 | `MarkdownHeaderParentSplitter`、标题分块测试 | 已验证 |
| 父子模式二次切割 | 超长片段保留完整父块（skipEmbedding=1），生成子块（parentChunkId 关联），子块之间有 overlap | `MarkdownHeaderParentSplitter.splitByChunkSize`、父子模式测试 | 已验证 |

## 3. 公共契约

| 对象 | 职责 | 关键约束 |
| --- | --- | --- |
| `DocumentSource` | 表达可重复打开的文档源 | 每次返回独立可关闭流；source 关闭幂等；关闭后不得再次打开 |
| `DocumentParseRequest` | 表达文档源、类型、扩展名、选型、选项和元数据 | 扩展名归一；选项和元数据不可变；值类型和数量受限 |
| `ParserSelection` | 表达 `DEFAULT` 或 `EXPLICIT` 选型 | `DEFAULT` 不得指定 provider；`EXPLICIT` 必须指定 provider |
| `DocumentParserCapability` | 声明 provider 支持的类型、精确扩展名、特性和可用性 | 文档类型和扩展名同时匹配，避免旧 Office 格式被误判为 MinerU 能力 |
| `DocumentParseResult<R>` | 包装框架结果与解析轨迹 | `map` 只转换 payload，保留 trace，不触发重新解析 |
| `DocumentParseError` | 表达 13 类失败原因 | 异常信息不得包含文档正文、认证信息或完整外部响应 |

## 4. 框架适配边界

### 4.1 Spring AI

- `SpringAiNativeDocumentParser` 聚合既有 `DocumentReaderStrategy`，保持原 `List<Document>` payload 和原生对象属性。
- `DocumentReaderFacade` 保留旧入口，并新增 selector 路径和带轨迹读取入口。
- `SpringAiMinerUDocumentParser` 只负责把共享 MinerU 中立结果适配为 Spring AI 文档；Markdown 结构性空白不经过旧清洗路径压缩。

### 4.2 LangChain4j

- `LangChain4jNativeDocumentParser` 使用 Apache Tika 解析并直接返回 LangChain4j 原生 `Document`。
- `LangChain4jDocumentParserFacade` 提供直接返回原生文档、带轨迹结果、`parseAndSplit`（解析+分块一站式）和 `split`（对已解析文档分块）四种入口。
- `LangChain4jDocumentSplitter` 作为分块策略路由入口，按配置创建 `recursive` 或 `markdown-header` 内部分块器。
- `MarkdownHeaderParentSplitter` 实现 Markdown 标题层级分块 + 父子模式二次切割，参考 know-engine 实现适配 fons4ai 包结构。
- `LangChain4jMinerUDocumentParser` 复用共享 MinerU provider，只在边界执行一次结果适配。

### 4.3 共存约束

- 两个框架维护不同 payload 类型的独立 `DocumentParserRegistry`。
- `MinerUClient` 和 `MinerUDocumentParser` 通过缺省 Bean 条件共享，避免重复协议实现。
- 双框架共存测试已验证注册表不冲突、native 路径不调用 MinerU、显式 MinerU 路径才发生协议调用。

## 5. 公共抽象与标准能力判定

| 抽象或机制 | 是否属于公共标准能力 | 判定依据 | 边界 |
| --- | --- | --- | --- |
| `DocumentParseProvider<R>` 与泛型结果信封 | 是 | 公共接口同时服务 Spring AI 与 LangChain4j 两套实现 | 不规定框架原生 payload 的内部结构 |
| Registry/Selector 选择骨架 | 是 | 两套框架共同使用相同注册、校验和失败语义 | 每个框架持有独立泛型注册表 |
| `DEFAULT` 固定 native、`EXPLICIT` 精确选择且无 fallback | 是，限 V1 | 正式需求、公共实现及跨框架测试一致 | 后续改变默认策略必须重新设计和验证 |
| native 解析具体实现 | 否，属于框架适配 | Spring AI 使用 Reader strategy，LangChain4j 使用 Apache Tika | 不将单个框架实现提升为平台唯一标准 |
| MinerU 同步 `/file_parse` 协议 | 否，属于 provider 适配 | 仅 MinerU 实现使用 | 协议变化需更新 MinerU 适配说明和测试 |

## 6. 能力规则

| 规则 | 状态 |
| --- | --- |
| V1 的 `DEFAULT` 永远为 native，不能通过配置改为 MinerU | 已验证 |
| 只有 `EXPLICIT + mineru` 且 provider 可用、格式受支持时才调用 MinerU | 已验证 |
| native 或显式 provider 失败时不进行静默 fallback | 已验证 |
| MinerU V1 同步处理单文件并返回 Markdown | 已验证 |
| MinerU 仅声明 PDF、图片、DOCX、PPTX、XLSX 等已确认格式，不把 DOC/PPT/XLS 计入自身能力 | 已验证 |
| 本次不修改向量化、切片、检索、持久化或数据库结构 | 已确认 |
| 本次不提供 LLM 自动选型、异步任务、ZIP、图片上传、对象存储或视觉描述 | 已确认 |
| 文档分块策略默认为 recursive，配置非法值时启动失败 | 已验证 |
| markdown-header 策略的 titleLevel 必须在 1-6 范围内 | 已验证 |
| 父子模式中父块标记 skipEmbedding=1 不向量化，子块携带 parentChunkId | 已验证 |
| 代码块标记（``` 和 ~~~）内的 # 不识别为标题 | 已验证 |
| 分块不修改原始 Document 内容，仅切分 | 已验证 |
| 文档分块不涉及向量化与入库，仅产出 TextSegment 列表 | 已确认 |

## 7. 可信状态与开放事项

- 已验证：公共契约、选择与注册规则、双框架 native/MinerU 适配、失败分类、默认不外发、Markdown 结构保持和三模块自动测试。
- 已验证：LangChain4j 文档分块（recursive + markdown-header 双策略、标题层级分块、父子模式二次切割、Facade 一站式入口），55 个测试全部通过。
- 待确认：外部文档传输的人工安全 Gate 尚未完成，因此不能表述为发布就绪。
- 待确认：RAG reactor 全量构建尚未形成通过证据；三个相关模块已分别在 JDK 21 下执行 `mvn -q test` 并通过。
- 待确认：`langchain4j-document-parser-apache-tika` 使用 `1.11.0-beta19`，与 LangChain4j 核心 `1.11.0` 的版本协同风险仍需复审。
- 待确认：`DocumentByParagraphSplitter` 对中文无空格分词支持有限，后续可通过引入 Token 计量改进。
