# 知识检索增强配置与资源文档

> 能力标识：`rag`
> 文档层级：技术能力域
> 文档状态：文档解析与文档分块配置与资源已汇总
> 更新日期：2026-07-30

## 1. 配置边界

Spring AI 与 LangChain4j 文档解析适配均绑定 `sys.rag.document-parser`。两套绑定类的字段类型实现不同，但 V1 的配置语义与默认值保持一致。

LangChain4j 文档分块绑定 `sys.rag.document-splitter`，与文档解析配置平行，保持职责分离。

## 2. 配置项

| 配置项 | 默认值 | 含义 | 状态 |
| --- | --- | --- | --- |
| `default-provider` | `native` | 默认解析 provider；V1 只允许 `native`，其他值启动校验失败 | 已验证 |
| `mineru.enabled` | `false` | 是否启用 MinerU provider | 已验证 |
| `mineru.base-url` | `http://localhost:8000` | MinerU HTTP API 基础地址 | 已验证 |
| `mineru.backend` | `pipeline` | MinerU 解析后端 | 已验证 |
| `mineru.connect-timeout` | `10s` | 建立连接的超时限制 | 已验证 |
| `mineru.read-timeout` | `5m` | 单次同步解析读取超时 | 已验证 |
| `mineru.max-file-size` | `100MB` | 发送至 MinerU 的单文件大小上限 | 已验证 |

### 文档分块配置（`sys.rag.document-splitter`）

| 配置项 | 默认值 | 含义 | 状态 |
| --- | --- | --- | --- |
| `strategy` | `recursive` | 分块策略：`recursive` 或 `markdown-header`，非法值启动失败 | 已验证 |
| `chunk-size` | `1000` | 单个分块最大字符数，必须大于 0 | 已验证 |
| `overlap` | `100` | 相邻分块重叠字符数，必须 >= 0 且 < chunk-size | 已验证 |
| `title-level` | `3` | 标题分块级别（1-6），仅 `markdown-header` 策略使用 | 已验证 |

## 3. 运行时资源

| 资源 | 所有权 | 生命周期 | 使用方 | 治理要求 |
| --- | --- | --- | --- | --- |
| `DocumentSource` 及其流/临时资源 | 调用方与公共文档源实现 | 单次或重复解析期间 | native、MinerU provider | 新流独立关闭；最终关闭 source；关闭幂等 |
| `MinerUClient` | RAG 自动配置 | 应用运行期 | 共享 `MinerUDocumentParser` | 双框架共存时只保留一份；超时和文件上限明确 |
| MinerU `/health` | 外部 MinerU 服务 | 显式 MinerU 解析前 | `MinerUClient` | 非 2xx、空响应或不可达视为不可用 |
| MinerU `/file_parse` | 外部 MinerU 服务 | 单次显式解析期 | `MinerUClient` | 同步单文件 multipart；严格校验 JSON 和 `md_content` |
| 框架 Registry/Selector | 各适配模块 | 应用运行期 | 框架 Facade | 两个框架独立注册表；构造后只读 |
| `LangChain4jDocumentSplitter` | LangChain4j 自动配置 | 应用运行期 | `LangChain4jDocumentParserFacade` | 不可变实例，线程安全；按配置策略创建内部分块器 |
| `MarkdownHeaderParentSplitter` | LangChain4j 自动配置 | 应用运行期 | `LangChain4jDocumentSplitter` | 仅 markdown-header 策略时创建；无状态工具类 |

## 4. 能力适配资源差异

| 适配对象 | 专属运行资源 | 共享资源 | 差异与治理边界 |
| --- | --- | --- | --- |
| Spring AI native | Reader strategy、Spring AI `Document` | 公共请求、Selector、trace | 保持既有策略与原生对象，不使用 MinerU adapter |
| LangChain4j native | Apache Tika parser、LangChain4j `Document` | 公共请求、Selector、trace | parser 依赖使用 beta 版本，版本协同待复审 |
| Spring AI MinerU | Spring AI adapter 与框架泛型 Registry | `MinerUClient`、中立 provider、公共配置语义 | 只在 MinerU 路径执行一次适配 |
| LangChain4j MinerU | LangChain4j adapter 与框架泛型 Registry | `MinerUClient`、中立 provider、公共配置语义 | 元数据按 LangChain4j 支持类型转换，只适配一次 |

## 5. 外部数据流与安全边界

- 默认 native 路径不向 MinerU 发送文档。
- 仅调用方显式选择 `mineru`，且 provider 启用、可用并支持请求格式时，原始文档二进制才会发送到配置的 MinerU 服务。
- MinerU 服务地址和部署边界由接入应用配置并治理；Fons4AI 不默认启用外发路径。
- 代码和测试已验证日志、轨迹和分类异常不应包含正文、认证信息或完整外部响应。
- 外部文档传输的合规性、真实部署安全和数据边界仍需人工 Gate，当前状态不是发布就绪。

## 6. 格式与输出约束

MinerU V1 声明支持 PDF、图片、DOCX、PPTX、XLSX 等已确认格式；旧 DOC、PPT、XLS 可由 native 实现处理，但不得写成 MinerU 能力。MinerU V1 返回 Markdown，不下载 ZIP、不上传图片、不接入对象存储，也不调用视觉模型生成图片描述。

## 7. 配置与依赖风险

| 风险 | 当前控制 | 剩余状态 |
| --- | --- | --- |
| 配置绕过默认 native 语义 | `default-provider` 启动校验只允许 `native` | 已验证 |
| 外部服务不可达或超时 | 健康检查、连接超时、读取超时和分类异常 | 已验证；真实环境待验证 |
| 大文件占用内存、磁盘或线程 | 文件大小上限、可重复文档源和流式 multipart | 已验证；生产容量待评估 |
| 文档敏感内容外发 | 默认关闭、必须显式选用、日志不记录正文 | 代码已验证；人工安全 Gate 待确认 |
| LangChain4j parser 依赖版本协同 | 当前采用 `1.11.0-beta19` | 待复审 |
| 双框架重复创建 MinerU 协议组件 | 缺省 Bean 条件和共存测试 | 已验证 |
| 分块策略配置非法值 | `LangChain4jDocumentSplitterProperties` @PostConstruct 校验 strategy 合法性 | 已验证 |
| 分块参数非法（chunkSize<=0、overlap<0、overlap>=chunkSize） | 构造器校验 + @PostConstruct 校验 | 已验证 |
| 中文分块精度不足 | `DocumentByParagraphSplitter` 对中文无空格分词支持有限 | 待确认，后续可引入 Token 计量 |
