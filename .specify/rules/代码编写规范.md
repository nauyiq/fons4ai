# 代码编写规范

> 适用仓库：Fons4AI
> 规则状态：首次生成
> 更新日期：2026-07-13

## 基本原则

- 编码前必须读取 `AGENTS.md`、命中的知识库文档、已有规则及相关源码，先确认需求、能力边界、公共契约和验证方式。
- 优先复用已有代码、工具函数、组件和扩展点；新增实现前必须确认现有能力不能满足需求。
- 变更必须保持最小范围，不得顺带重构、格式化或修改无关文件；工作区已有改动必须保留。
- 优先遵循现有 Maven 多模块结构、Java/Spring Boot Starter 模式和已存在的扩展点，不得未经设计批准引入新的框架、基础设施或供应商绑定。
- `*-common` 用于稳定的公共契约、请求响应对象、常量和与具体实现解耦的抽象；`*-spring-ai-starter` 用于 Spring AI 适配、自动配置和运行实现。新增依赖不得造成公共模块反向依赖实现模块。
- 模块边界不等同于最终能力边界。新增实现应围绕 Agent 编排、工具管理、RAG、AI 能力接入的职责组织，不得虚构上层业务领域。
- Spring AI 是当前适配实现。除非公共契约本身明确需要，不得让新的核心抽象直接暴露供应商或框架专有类型。
- 修改公共 API、配置前缀、序列化结构、枚举值或异常码前，必须评估兼容性、调用方影响和迁移方式；破坏性变更必须先确认。

## 工具类与复用

- 新增逻辑前必须定向搜索已有接口、工具类、策略、工厂、注册中心、配置属性、结果对象和异常体系，能复用时不得重复实现。
- 优先复用项目现有的结果封装、异常类型、字符串与集合工具、Spring 扩展点和序列化方式；不得为单一调用创建功能重复的工具类。
- 工具类必须无业务状态、职责单一并明确空值行为；仅服务一个实现类的逻辑优先保留为私有方法，不提前抽象为公共工具。
- 对象或数据转换遵循以下优先级：先复用项目既有映射或序列化模式，再复用已有转换器，最后才新增转换器。
- 新增 5 个以上字段映射，或同类字段搬运重复出现时，必须优先抽取可复用转换器；不使用转换器时，应在实施报告中说明原因和后续维护成本。
- 不得使用 JSON 序列化/反序列化替代类型安全的普通对象转换，除非边界本身就是 JSON 契约并已处理格式错误。
- 新增 Spring Bean 优先使用构造器注入。只有生命周期或动态发现机制确有需要时才使用静态容器取 Bean，并说明原因。

## 代码风格

- Java 代码使用 4 个空格缩进，类、方法和变量命名必须表达职责；禁止无业务语义缩写、拼音命名和魔法数字。
- 包名使用全小写；类名使用大驼峰；方法和变量使用小驼峰；常量使用大写下划线，并集中表达单位、范围或协议语义。
- 一个类只承担一个主要职责。复杂流程优先拆为有语义的私有方法、策略或适配器，不以超长方法和多层条件分支堆叠行为。
- 能通过构造器确定且不应变化的依赖和字段应声明为 `final`；共享可变状态必须说明线程安全策略。
- 使用 Lombok 时只启用确有必要的注解。包含密码、Token、密钥、连接信息或敏感请求数据的类禁止生成会输出全部字段的 `toString`。
- 公共类、公共方法、接口方法、Request、Response 必须有中文注释，说明职责、参数、返回值和异常边界；不得保留空洞的 `@return`、`@param`。
- 安全、权限、Token、密钥、状态、时间、ID、金额、外部资源引用等关键字段，必须写明语义、格式、单位、取值边界或生命周期。
- 注释解释设计原因、约束和非显然逻辑，不复述代码。TODO 必须包含明确问题或后续动作，不得把占位实现描述为已完成能力。
- 新增代码保持与所在文件一致的导入、空行和注解顺序；禁止仅为个人偏好批量格式化已有文件。

## DDD-lite 编码约束

- 本项目采用轻量边界治理，不强制套用实体、聚合、仓储等完整 DDD 模板，也不得为技术能力虚构业务领域对象。
- 公共契约表达稳定能力语义；具体框架、模型服务商、数据库、Redis、MCP 或第三方 API 的细节收敛在适配和基础设施实现中。
- 核心流程依赖抽象或稳定契约，适配器依赖核心契约；禁止核心契约反向依赖某个供应商实现。
- 新增策略、提供者、解析器或工厂时，应复用现有扩展机制，明确唯一标识、支持条件、未知类型行为和冲突处理规则。
- 聚合状态或任务生命周期变更必须集中维护不变量，明确并发、幂等、超时、停止、清理和资源释放行为，避免调用方直接修改内部状态。
- 跨能力域调用只暴露必要契约，不共享可变内部对象，不以公共工具包规避依赖方向。

## API 接口设计

- API、SPI 和公共接口先定义语义、输入、输出、失败行为及兼容策略，再选择具体框架类型或注解。
- Request、Response、事件和工具元数据必须使用明确类型；禁止使用无边界的 `Map<String, Object>` 承载稳定公共契约。确需开放元数据时，必须说明允许的键、值类型和序列化边界。
- 输入必须在系统边界校验空值、格式、长度、范围、枚举和组合条件；内部方法不得重复假定未经验证的外部输入可信。
- 返回值应明确“未找到”“空结果”“执行失败”和“部分成功”的差异，不得混用 `null`、空集合和异常表达同一语义。
- 公共接口不得泄露密码、Token、连接串、内部异常堆栈或供应商原始敏感响应。
- 对外 ID、时间、状态和外部资源引用必须保持稳定口径。时间需明确时区和格式；状态需明确合法值与迁移边界；外部引用需校验来源与访问权限。
- 修改公共方法签名、配置项名称、默认值、序列化字段或枚举时，必须补充兼容性测试或迁移说明。

## 数据映射与安全

- 字段映射必须逐项核对名称、类型、空值、默认值、精度和枚举口径；禁止依赖字段顺序或未经验证的隐式类型转换。
- 涉及金额时必须明确币种、最小货币单位、精度和舍入规则，不得使用浮点类型承载金额。
- 涉及日期时间时必须明确时区、存储类型和序列化格式；禁止在未说明时区的情况下混用本地时间与时间戳。
- 状态字段必须有唯一口径并限制合法迁移；外部流水号、请求号或幂等键必须明确唯一性、重试和重复处理策略。
- 敏感数据必须按分类采取最小采集、最小返回、日志脱敏、存储加密和传输保护；密钥不得与密文存放在同一配置或代码中。
- 数据和外部资源访问必须执行最小权限原则；高风险读取、写入和权限变更必须保留操作者、时间、对象、来源和结果等必要审计信息。
- Request、Response、配置对象和日志对象之间转换时，必须显式排除密码、Token、密钥、连接串、认证头及其他不应跨边界传播的字段。

## 异常与日志

- 异常按边界转换：底层异常可记录并包装为项目异常或结果码，但必须保留原始 cause；不得静默吞掉异常或统一返回无信息的失败结果。
- 只捕获能够处理、补充上下文或转换边界语义的异常。禁止使用大范围 `catch (Exception)` 隐藏编程错误；确需兜底时必须记录上下文并保持可诊断性。
- 日志使用参数化占位符，包含定位问题所需的能力、操作、关键非敏感标识和结果；禁止字符串拼接生成日志。
- 同一异常在同一调用链只由最合适的边界记录完整堆栈，避免逐层重复打印。
- 密码、Token、密钥、连接串、认证头、完整提示词、文档正文、个人信息和第三方敏感响应不得写入日志；对象自动输出前必须确认已脱敏。
- 日志级别必须与影响匹配：可恢复或预期分支使用 `debug`/`info`，需要关注但已降级处理使用 `warn`，导致操作失败且需排查时使用 `error`。
- 不得记录可能造成提示词、模型输入输出、文件内容或工具参数泄漏的完整请求；必要时只记录长度、摘要、类型和脱敏标识。

## 数据访问与事务

- 当前仓库未确认统一业务数据库模型。新增数据访问、DDL 或迁移脚本前，必须先确认数据所有权、表结构、访问路径和回滚方案，不得依据猜测编码。
- 字段映射必须逐项核对名称、类型、空值、默认值、精度和枚举口径；禁止依赖字段顺序或隐式类型转换。
- 涉及金额时必须明确币种、最小货币单位、精度和舍入规则，不得使用浮点类型承载金额。
- 涉及日期时间时必须明确时区、存储类型和序列化格式；禁止在未说明时区的情况下混用本地时间与时间戳。
- 状态字段必须有唯一口径并限制合法迁移；外部流水号、请求号或幂等键必须明确唯一性、重试和重复处理策略。
- 敏感数据必须按分类采取最小采集、最小返回、日志脱敏、存储加密和传输保护；密钥不得与密文存放在同一配置或代码中。
- 数据访问必须执行最小权限原则，并为高风险写操作保留必要的操作者、时间、对象和结果审计信息。
- 事务边界应围绕一个完整一致性目标，避免把远程调用、模型调用或长耗时任务无约束地包在数据库事务中。
- 事务内发生异常时不得吞掉导致错误提交；异步、消息、缓存和外部系统参与时必须明确一致性、幂等、补偿和失败恢复策略。
- DDL 的表注释、字段注释和脚本说明默认使用中文；每个新增或变更脚本必须包含执行前提、影响范围、验证方法和回滚说明。
- 索引必须绑定明确的查询、排序、关联、唯一性或运维审计场景，并记录设计依据；禁止按字段清单机械建索引，索引数量应保持克制。
- DDL 审查清单至少包含：表注释、字段注释、类型与默认值、空值约束、主键与唯一性、索引依据、数据兼容、锁表风险、执行顺序、验证与回滚。

## 测试与验证

- 每次代码变更必须提供与风险匹配的新鲜验证证据，至少记录变更范围、验证命令、结果和未验证项。
- 新增公共契约、状态转换、并发控制、安全权限、缓存、数据库、RPC、网关、MQ、限流、事务或外部工具适配时，默认先编写可复现失败的测试，再完成实现。
- 修复缺陷必须补充能复现缺陷的测试；测试应在修复前失败、修复后通过，且不得只断言“不抛异常”。
- 单元测试覆盖正常、边界、异常和资源清理路径；并发、超时、重试、停止、幂等和降级行为必须使用可重复的确定性验证。
- 测试不得依赖真实生产账号、密钥、外部网络或不可控服务。外部模型、MCP、Redis、PgVector 和第三方 API 应使用替身、容器化测试资源或明确隔离的测试环境。
- 多模块 Maven 验证优先从受影响的最小模块开始，再按影响范围执行关联模块测试或构建；命令失败时必须保留失败原因，不得声称通过。
- 纯注释或文档性代码调整可使用编译、静态检查或人工审查作为等价验证，但必须说明未运行测试的原因。
- 当前仓库未发现现有测试源码或统一覆盖率门槛；新增行为不得以此为由跳过测试，具体测试框架和覆盖率阈值在引入前标记为 `待确认`。

## 禁止事项

- 禁止修改与当前需求无关的代码、配置、依赖、文档或格式。
- 禁止编造接口、字段、表结构、第三方 API、状态值、异常码、配置项或运行环境。
- 禁止未经确认删除核心逻辑、公共契约、兼容分支、资源清理或安全校验。
- 禁止把 Spring AI、PgVector、Redis/Redisson、MCP、Tavily 或任一供应商实现固化为长期唯一标准。
- 禁止在源码、配置、测试、日志、注释和示例中提交真实密码、Token、密钥、连接串或敏感数据。
- 禁止通过空捕获、返回 `null`、伪造成功结果、关闭测试或降低断言来掩盖失败。
- 禁止在没有测试或等价验证证据时声称代码已完成、缺陷已修复或兼容性已保证。
- 禁止未经设计审查和用户确认修改数据库结构、公共 API、配置前缀或跨模块依赖方向。
