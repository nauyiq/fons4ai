# CR-001 扩展 Markdown 标题分块与父子模式

> CR ID: CR-001
> 变更类型: 扩展
> SDD 等级: S1
> 目标功能: spec/features/20260729/LangChain4j文档分块
> 创建日期: 2026-07-29
> 实现确认状态: pending

## 变更概述

在现有 recursive 分块策略基础上，新增 Markdown 标题层级分块策略（父子模式），支持按 `#`~`######` 标题层级切分文档，超长片段通过父子关联保留上下文完整性。

## 变更原因

MinerU 返回的是 Markdown 文档，天然有标题层级结构。当前 `recursive()` 策略不理解文档结构，可能在标题中间切断。标题分块策略能按语义边界切分，父子模式确保超长片段既保留完整上下文（父块）又支持精确向量化（子块）。

## 影响分析

### 需求与 AC 变化

| 新增 | 内容 |
| --- | --- |
| REQ-007 | 支持 Markdown 标题层级分块策略，可配置标题切分级别（1-6） |
| REQ-008 | 超长片段（超出 chunkSize）采用父子模式：保留完整父块（标记 skipEmbedding），生成子块（parentChunkId 关联） |
| AC-007 | 给定含 Markdown 标题的文档，按配置的标题级别切分，每个分块携带标题层级元数据 |
| AC-008 | 给定超长片段，保留完整父块（skipEmbedding=1），生成带 parentChunkId 的子块，子块之间有 overlap 重叠 |
| AC-009 | 给定配置 strategy=markdown-header，应用启动后使用标题分块策略；strategy=recursive 使用递归策略 |

### 技术设计影响

- 新增 `MarkdownHeaderParentTextSplitter` 类（参考 know-engine 实现，适配 fons4ai 包结构）
- 新增策略选择机制（`SplitStrategy` 枚举或工厂）
- `LangChain4jDocumentSplitter` 扩展为策略路由入口
- 配置扩展：新增 `strategy`、`title-level` 字段
- 新增元数据键常量（`chunkId`、`parentChunkId`、`skipEmbedding`、`headerLevel`）

### 数据结构与 DDL 影响

无。分块在内存中处理，不涉及持久化。

### 回归风险

- Facade 的 `parseAndSplit` 方法签名不变，内部策略切换透明
- 旧测试全部回归通过

是。影响类型为技术方案。影响说明为 LangChain4j Markdown 标题分块（父子模式）能力，包括策略选择机制、标题栈、代码块保护、父子关联元数据。
