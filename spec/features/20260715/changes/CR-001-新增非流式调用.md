# CR-001 新增非流式调用

> 功能标识：`agent-instance-sharing`
> 变更类型：契约变更（能力扩展）
> SDD 等级：`S2`
> 文档状态：正式
> 创建日期：2026-07-15

## 1. 变更摘要

- 变更一句话说明：在现有流式调用和显式 `AgentRun` 能力之外，增加同步 `call(request)`，一次返回结构化 `AgentRunResult`。
- 本次变更结论：采用用户确认的推荐方案；同步非流式调用复用 `start(request).completion()`，响应式非流式调用继续直接使用 `completion()`，不增加 `callAsync()`。
- 是否建议新建 feature：否；本次只新增一个公共调用入口和一个 AC，不替换共享 Agent 的核心生命周期、任务租约或各 Agent 执行流程，影响范围低于 70%。

## 2. 变更原因

- 用户诉求：共享 Agent 除流式输出外还必须支持非流式输出能力。
- 业务或技术背景：框架接入方既有 SSE/流式消费场景，也有服务内部同步获得完整结果的场景；只暴露事件流会迫使调用方自行聚合 JSON，容易形成重复执行逻辑和不完整结果。
- 不变更的影响：若不增加统一同步入口，调用方只能直接组合响应式 completion 或自行消费流，公共 API 易用性和结果语义不完整。

- 技术设计与当前实现一致性：存在预期差异；技术设计描述目标态，当前代码属于变更前基线，不构成事实冲突。
- 前置限制：无；用户已明确确认同步 `call(request)` 返回结构化 `AgentRunResult`，响应式场景复用 `start(request).completion()`。

## 4. 影响范围

- 需求影响：有，新增 REQ-008、BR-008、AC-010，并补充同步调用角色、流程和质量边界。
- 技术设计影响：有，扩展 Agent 公共契约、Run 启动语义、同步等待线程边界、异常语义和双模式一致性验证。
- 代码影响：有，目标涉及 Agent Common 的 `Agent`/`AgentRun`/`AgentRunResult` 契约、`DefaultAgentRun` 启动控制和各 Agent 类型的非流式契约测试。
- 测试影响：有，新增成功、失败、拒绝、单次执行、同步/流式一致性及 Reactor 事件循环线程快速失败测试。
- 接口/契约影响：有，`Agent` 新增同步 `AgentRunResult call(AgentChatRequest request)`；现有 `stream(request)` 和客户端 JSON 不变。
- 权限/安全影响：无新增权限；非流式结果仍只能包含本 Run 已授权的技能、工具和资源衍生结果，且不得泄露内部异常堆栈。
- 兼容/回滚影响：新增方法属于向前扩展；当前无业务接入。回滚可移除 `call` 和对应测试，不影响 `start`、`completion` 或 `stream`。
- UI 设计确认：不适用，原因：本 CR 不涉及页面、前端、控制台或交互型交付物。

- 变更 AC：无；AC-001 至 AC-009 保持原语义。
- 删除 AC：无。
- REQ/AC 映射调整：新增 REQ-008 -> AC-010；原有映射不变。

## 6. 技术设计影响

- API/RPC/消息影响：Java 公共 API 新增同步等待型 `call(request)`；不修改 RPC、Redis 消息和客户端流式消息。
- 领域对象/业务规则影响：Agent/AgentRun 增加“一个调用只创建并启动一个 Run”的运行不变量；非流式结果不得由第二次模型调用或流事件解析产生。
- 状态流转影响：不新增状态；`call` 等待现有 CREATED -> RUNNING -> 终态流程，`completion()` 对成功、失败、取消和拒绝恰好产生一个结果。
- 事务/一致性影响：不涉及数据库事务；`call` 与 `stream` 共享任务登记、原子终态、Hook 和精确任务释放语义。
- 工具包/依赖影响：不新增依赖；复用 Reactor 和现有公共结果类型。

## 8. 回归与回滚

- 回归风险：有；可能占用 Reactor 事件循环线程、因 completion/events 重复订阅启动两次执行，或为非流式另写一套 Agent 循环造成结果漂移。
- 回归验证范围：Agent 公共 API、Run `startOnce`、BaseAgent、ReAct/Web Search、Plan-Execute、Skills、任务清理、Hook、流式协议和受影响 Maven Reactor 构建。
- 回滚方案：删除新增 `call(request)` 默认实现、线程边界错误和 T009 对应测试；保留 `start(request).completion()` 与 `stream(request)`，无需数据或 Redis 回滚。
- S2 风险门禁：需要；公共 API 变更必须验证兼容、线程边界、单次启动、结果非空、异常安全和全 Agent 类型一致性。

## 9. 长期知识影响

- 是否产生长期知识影响：是。
