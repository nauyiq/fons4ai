# 四能力模块拆分需求说明书

> 功能标识：`four-capability-module-split`
> 版本：V1.0.0
> 文档状态：已确认
> 创建日期：2026-07-13
> 更新日期：2026-07-13

## 一句话说明

将 Fons4AI 的现有能力按照 Agent 编排、工具管理、知识检索增强和 AI 能力接入重新归属，使各能力能够独立演进和按需接入，同时保持现有功能行为不变。

## 需求澄清摘要

### 已确认内容

本需求已接受 2 个澄清问题。

| 序号 | 澄清问题 | 已确认结论 | 影响范围 |
| --- | --- | --- | --- |
| Q1 | 拆分是否同时改变现有功能行为 | 采用结构重构方案，仅调整能力归属、公共命名、配置命名和必要依赖边界，不增加或改变现有功能行为 | 需求范围、验收、回归 |
| Q2 | 新能力命名与兼容策略 | 迁出内容使用目标能力的新命名；配置统一以 `sys` 开头并按能力分组；不保留旧包门面、旧配置别名或兼容层 | 公共契约、接入迁移、回滚 |

- 无。

## 背景与目标

- 背景：Fons4AI 已确认包含 Agent 编排、工具管理、知识检索增强和 AI 能力接入四项能力，但当前部分工具、图像生成和多模态内容归属在 Agent 或 RAG 范围内。
- 当前问题：物理归属与能力职责不一致，导致独立接入、依赖治理和后续扩展边界不清晰。
- 目标：形成四个职责清晰、可以独立演进和按需接入的能力单元；将归属错误的内容迁回目标能力；统一新的公共命名和配置分组；保持现有运行行为不变。
- 不做会怎样：工具管理和 AI 能力继续与 Agent、RAG 混合演进，新增适配器或模型能力时将持续扩大跨能力影响。

## 需求范围

### 本次包含

- 按 Agent 编排、工具管理、知识检索增强、AI 能力接入四项能力重新组织现有发布单元。
- 保留现有 Agent 与知识检索增强的顶层归属名称，新增工具管理和 AI 能力接入的独立归属。
- 将工具定义、注册、提供者、调用结果解析及现有工具接入迁入工具管理能力。
- 将图像生成和多模态相关内容迁入 AI 能力接入能力。
- 将迁出内容改用目标能力的公共命名，不保留旧包门面。
- 将配置统一为以 `sys` 开头、按能力分组的新命名，不保留旧配置别名。
- 调整能力之间的依赖方向，并验证四项能力可以按需接入。
- 对拆分前已有的 Agent、工具调用、知识检索、图像生成和多模态行为执行回归验证。

### 本次不包含

- 不新增 Agent 类型、工具提供商、向量存储、模型服务商或 AI 功能。
- 不改变现有任务生命周期、工具调用、知识检索、图像生成和多模态处理规则。
- 不新增非 Spring AI 的框架适配实现。
- 不修改持久化数据结构或执行数据库迁移。
- 不提供旧包名、旧配置名称或旧发布单元的兼容层。

## 角色与场景

| 角色或参与方 | 使用场景 | 触发条件 | 期望结果 |
| --- | --- | --- | --- |
| Fons4AI 维护者 | 新增或维护某项能力 | 需要定位能力归属或调整实现 | 能够在单一明确的能力边界内完成变更 |
| 上层应用开发者 | 按需接入 AI 能力 | 应用只需要四项能力中的部分能力 | 只引入需要的能力即可完成接入 |
| 现有接入方 | 升级到拆分后的版本 | 旧包和旧配置不再兼容 | 根据新的能力命名完成一次性迁移，并获得与升级前一致的功能行为 |

| BR-001 | 能力归属以职责为准，不能因为当前代码位置而继续保留错误归属 | 内容迁移 | 无 |
| BR-002 | Agent 编排负责执行与生命周期，不拥有通用工具管理和独立 AI 服务能力 | 能力边界 | Agent 对其他能力的调用关系可以保留 |

## 业务流程

### 主要流程

1. 维护者按四项能力识别现有内容的职责归属。
2. 归属正确的内容保留，归属错误的内容迁入目标能力。
3. 迁出内容改用目标能力的公共命名和配置分组。
4. 上层应用根据需要接入对应能力，并使用新的公共命名完成配置。
5. 项目执行完整构建和现有功能回归，确认拆分前后行为一致。

### 异常或分支

- 现有接入方仍使用旧包或旧配置时，升级后不保证继续编译、装配或运行，必须改用新命名。
- 若迁移过程中发现现有内容同时承担多个能力职责，应在技术设计中拆分契约和实现，不得将整块代码随意归入单一能力。
- 若解除耦合需要改变现有可观察行为，必须停止实现并返回需求变更流程重新确认。

## 验收标准

- AC-001：Given Fons4AI 完成拆分，when 维护者查看可发布能力单元，then 能够明确识别 Agent 编排、工具管理、知识检索增强和 AI 能力接入四项独立能力。关联需求：REQ-001。
- AC-002：Given 现有工具、图像生成和多模态内容完成归属检查，when 查看拆分后的内容位置，then 工具相关内容只归属于工具管理，图像生成和多模态相关内容只归属于 AI 能力接入，Agent 与知识检索增强中不再保留原实现。关联需求：REQ-002。
- AC-003：Given 接入方升级到拆分后的版本，when 使用目标能力的新公共命名和以 `sys` 开头的能力配置，then 对应能力可以正常装配；when 继续使用旧包或旧配置，then 不提供兼容保证。关联需求：REQ-003。
- AC-004：Given 拆分前已有的 Agent、工具调用、知识检索、图像生成和多模态场景，when 使用新命名执行等价调用，then 可观察结果与拆分前一致。关联需求：REQ-004。
- AC-005：Given 上层应用只需要四项能力中的一项或部分能力，when 选择对应能力接入，then 无关能力不会成为非必要的强制接入项。关联需求：REQ-001、REQ-005。
- AC-006：Given 所有内容迁移和依赖调整完成，when 执行完整项目构建及计划内回归检查，then 构建成功且验证结果、未验证项和剩余风险均有记录。关联需求：REQ-006。

## 质量要求

- 性能：拆分不得引入新的远程调用、重复模型调用或明显额外初始化开销；现有性能行为保持不变。
- 安全：配置迁移不得输出或提交真实密钥、Token、连接串；现有敏感配置处理要求保持不变。
- 兼容：明确采用破坏性升级，不兼容旧包名、旧配置名称和旧能力归属；除此之外的功能行为必须保持兼容。
- 可用性：四项能力应可独立装配；单项能力缺失时，不应导致与其无关的能力无条件启动失败。
- 可维护性：能力职责、公共命名和依赖方向必须一致，不得通过公共工具包或循环依赖重新形成隐式耦合。

## 风险与待确认

### 风险

- 这是跨核心能力的 S2 破坏性重构，包名、配置和发布单元同时变化，回归范围较大。
- 仓库当前未发现现有测试源码，行为不变需要在任务规划中补充可重复的验证基线和必要测试。
- 当前工作区已有与 Agent 提示词和执行流程相关的未提交修改，实施时必须与其共存，不得覆盖。

### 假设

- 本次不要求兼容任何旧包、旧配置或旧发布单元。
- 本次不改变数据库、缓存键、消息主题或外部服务协议；如果实施发现此类变化，必须返回需求或设计阶段确认。
- Spring AI 继续作为当前实现适配，本次不引入新的 AI 开发框架。

### 待确认

- 无阻塞项。具体发布版本号、发布说明格式和包迁移映射表样式可在发布前确定，不阻塞技术设计。
