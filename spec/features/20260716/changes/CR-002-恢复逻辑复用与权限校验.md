# CR-002 恢复逻辑复用与权限校验

> 功能标识：`agent-runtime-approval`
> 变更类型：重构
> SDD 等级：`S2`
> 文档状态：正式
> 创建日期：2026-07-20

## 1. 变更摘要

- 变更一句话说明：保持现有 AgentResumeRequest 和 Alibaba Saver 接入不变，提取三类 Agent 的重复恢复校验，并验证 Skills 恢复不会因目录 reload 提升权限。
- 本次变更结论：只做内部代码复用和既有权限不变量修复，不新增 Runtime、Store、恢复 API、配置或分布式能力。
- 是否建议新建 feature：否；恢复语义、审批点和下游职责均属于现有 `agent-runtime-approval`。

## 2. 变更原因

- 用户诉求：优先精简逻辑和提取重复代码，不引入新的下游接入或架构逻辑。
- 业务或技术背景：React、Plan、Skills 分别重复 threadId 关联、RunnableConfig 构建、checkpoint 查找和部分决定校验；Skills 恢复时重新构建 Registry/Resolver，需要用确定性测试证明仍绑定原 Run 权限。
- 不变更的影响：恢复代码继续分散，错误语义易漂移；技能目录在等待期间更新时存在使用最新授权视图的风险。

- 技术设计与当前实现一致性：主体一致；新增 §13 明确本轮只提取内部恢复 Support 和加固 Skills 权限快照。
- 前置限制：无；依赖智能体实例共享 CR-002/T010 的安全终态清理。

## 8. 回归与回滚

- 回归风险：有；公共校验提取可能使三个 Agent 的 threadId 格式、异常类型或 checkpoint 选择发生漂移。
- 回归验证范围：React、Plan、Skills 的 APPROVE/EDIT/REJECT、WAITING、checkpoint 缺失、并发 Run 和 Skills 资源安全。
- 回滚方案：T017/T018 分别以小范围 diff 回退，不改变 Saver 数据或下游请求结构。
- S2 风险门禁：需要；恢复和权限属于安全关键路径，必须有自动化负向测试和独立 Review。
