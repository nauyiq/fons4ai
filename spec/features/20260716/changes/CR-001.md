# CR-001 审批能力轻量化收缩与可读性治理

> 功能标识：`agent-runtime-approval`
> 变更类型：重构、契约变更
> SDD 等级：`S2`
> 文档状态：正式
> 创建日期：2026-07-16

## 1. 变更摘要

- 变更一句话说明：把已经膨胀为通用分布式审批平台的实现收缩为轻量、可插拔的 HITL 扩展层，并为所有 Agent 与 Skills 核心类补齐可读的流程和契约注释。
- 本次变更结论：保留下游策略编排、关键动作前暂停、批准/编辑/拒绝、流式中断、非流式等待和运行隔离；删除或延期通用持久化、跨实例恢复、审计平台、Retention、加密信封和按 Agent 暴露的 ResumeHandler。
- 是否建议新建 feature：否。原能力仍是 `agent-runtime-approval`，16 个原 AC 中默认关闭、策略外置、暂停、批准/拒绝、拒绝反馈、超时/取消和幂等核心语义仍保留；跨重启/多实例、通用审计与数据治理共 7 项转为延期，未超过 70% 替换阈值。

## 2. 变更原因

- 用户诉求：当前实现耗时过长、抽象层级过多，框架负责人难以理解 Agent 如何审批以及下游如何接入；用户明确要求按“轻量可插拔”方向收缩，并为所有字段、枚举、方法入口、关键逻辑、Skills 类和 Agent 流程增加详细注释。
- 技术背景：Spring AI Alibaba 已提供 `HumanInTheLoopHook`、Graph interruption、Saver 和基于同一 thread 的恢复能力；Fons4AI 不应再次实现一套供应商无关的分布式 checkpoint、恢复路由和审计平台。
- 不变更的影响：不改变业务审批 UI、身份鉴权、多人会签/或签和审批规则归属下游的边界；不改变共享 Agent + 每 Run 隔离状态的架构；不新增数据库 DDL 或外部依赖。

- 前置限制：无。用户已明确选择轻量化方向并要求开始执行；本 CR 先固化范围，不在本阶段修改业务代码。

## 4. 影响范围

- 需求影响：有。跨客户端断线、应用重启、Fons4AI 通用跨实例恢复、完整审计和独立 Retention 从 V1 必须项调整为延期项；新增轻量 Adapter、原生内核恢复和全面可读性要求。
- 技术设计影响：有。移除通用分布式运行时，改为统一公共 HITL 契约 + 内核 Adapter；自研 Agent V1 只支持同进程恢复，Alibaba Agent 复用原生 Saver 恢复。
- 代码影响：有。涉及 Agent Common 审批契约、Starter 审批实现、自动配置、Base/React/Web/Plan/Skills 适配和对应测试。
- 测试影响：有。删除或延期 Redis/CAS/fencing/加密/Retention/跨实例平台测试，新增轻量运行时、动作前无副作用、原生恢复、共享实例隔离和注释可读性检查。
- 接口/契约影响：有。保留请求级策略入口和 WAITING/中断事件；用轻量 `HumanInTheLoopRuntime`/`HumanInterrupt` 取代查询、审计、checkpoint 和 ResumeHandler 契约。当前无下游业务接入，允许在发布前进行不兼容清理。
- 权限/安全影响：有。审批只允许放行应用原本已授权的动作；审批意见按不可信输入处理；框架不因删除通用加密平台而开放本地文件、Shell、技能或工具权限。
- 兼容/回滚影响：现有审批实现尚未通过 Gate 且无下游接入，可直接回滚到本 CR 前工作区；Agent 共享和 Skills 非审批能力必须保留。

## 6. 技术设计影响

- API/RPC/消息影响：保留 `AgentRunOptions`、审批点、上下文、策略、要求、请求、决定、动作、拒绝模式、`WAITING_APPROVAL`、pending ID 和审批中断事件；移除通用 RunQuery/Audit/Checkpoint/DecisionStatus 等平台型契约。
- 领域对象/业务规则影响：轻量运行时只维护单个中断的 `PENDING/RESOLVED` 原子状态和一次性 continuation，不再维护分布式审批聚合。
- 状态流转影响：自研 Agent 在当前进程内 `RUNNING -> WAITING_APPROVAL -> RUNNING/终态`；Alibaba Agent 使用原生 Graph interruption/Saver；进程重启后的自研恢复明确返回不可恢复，不伪装成功。
- 事务/一致性影响：不再承诺跨实例 CAS、fencing、outbox 或审计一致性；同一进程内保证首个决定生效和动作最多执行一次。
- 工具包/依赖影响：不新增依赖；Skills 优先复用 Spring AI Alibaba 原生 HITL，React/Web 复用统一动作执行拦截器，Plan 复用 Graph interrupt 节点。

## 7. 数据结构与 DDL 影响

- 是否涉及持久化结构变更：否。
- SQL 当前结构快照：不适用。
- SQL DDL 动作：无。
- 执行型变更 DDL、执行方式和执行确认：均不适用。
- 运行数据变化：删除本功能尚未发布的 Redisson 审批聚合、事件、审计、checkpoint 和 retention 适配；轻量 V1 仅保存进程内中断状态，Alibaba 原生 Saver 的存储由具体内核配置负责。

## 8. 回归与回滚

- 回归风险：审批代码与此前共享 Agent/Skills 改动交织，整文件回退可能误删有效能力；删除类型也可能留下 Builder、自动配置或测试引用。
- 回归验证范围：Agent Common 编译与契约测试；Base/React/Web/Plan/Skills 流式和非流式路径；共享 Agent 并发 Run 隔离；Skills 渐进加载、资源边界和工具冲突测试。
- 回滚方案：按任务逐阶段保留小批量 diff；T012 完成后先进行负责人可读性 Gate，再进入 Skills/Plan；任一阶段失败时只回滚本 CR 新增的小范围变更，不重置工作树。
- S2 风险门禁：需要。公共契约清理、共享实例并发、HITL 副作用边界和供应商适配必须经过独立 Spec Review、Code Review 和用户人工 Gate。

## 9. 长期知识影响

- 是否产生长期知识影响：是。
- 影响类型：技术方案、接口契约、治理规则。
- 影响说明：Agent 编排能力的 HITL 长期边界调整为“框架提供轻量扩展契约，具体内核负责 checkpoint/恢复，下游负责策略与交互”，不再把 Fons4AI 描述为通用分布式审批平台。
- 处理边界：知识沉淀由 `fons4ai-knowledge-summary` 在用户显式触发后处理，本 CR 不生成知识同步任务或知识汇总交接任务。
