## 现象

仓库级路由规则提供 SDD、BUG 修复和快速路径等流程入口，但没有明确的“检查单个类并直接修复”的轻量默认路径。开发者的首轮意图是静态代码审查：要求检查单个类的逻辑自洽性并先列问题；随后明确要求直接修复，且不要求补充功能需求、故障复现或流程产物。

如果 Agent 将“发现代码可能不合理”或“用户要求修复”自动推断为 BUG 修复或 SDD，便会生成与用户目标无关的复现、修复报告、需求设计或任务拆解，增加简单 Vibe Coding 的流程负担。

## 期望行为

建议将“检查并直接修复”作为独立的轻量默认路径：

1. 用户要求检查、评审、找问题或先列清单时，执行只读代码审查，不触发 SDD、BUG 修复或快速路径技能。
2. 用户在审查后明确要求修复时，默认直接执行范围内的修改与针对性编译/测试验证，仍不触发 SDD 或 BUG 修复。
3. 仅当用户明确在处理既有故障、异常或回归时，才进入 BUG 修复；仅当用户明确提出功能需求、需求变更或需要规格化交付时，才进入 SDD。若直接修复会明显超出用户指定范围，应先请求确认，而非自动升级流程。
